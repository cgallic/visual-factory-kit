# Performance-Oriented Carousel System

## Design position

This system adapts **proven carousel mechanics** into original Visual Factory templates. It does not copy a specific creator, post, brand, or platform interface. Its purpose is to make useful content easier to stop on, swipe through, save, and share by pairing a strong cover promise with low-friction, repeatable slide structures.

The research consistently emphasizes a **hook → substance → action** sequence, minimal cover copy, one idea per middle slide, recurring grid and typography rules, small non-competing brand marks, slide numbering, and a specific closing action. [1] [2]

> The unit of performance is not the decorative style. It is the reader’s willingness to understand slide one, continue to slide two, and retain enough utility to save or share the final sequence.

## The twelve original carousel slide roles

| Role | Template key | Purpose | Primary design pattern |
| --- | --- | --- | --- |
| Cover hook | `carousel_viral_cover` | Create curiosity or a clear value promise | Oversized 4–9-word hook, slide count, micro-brand mark, visual tension |
| Pattern interrupt | `carousel_pattern_interrupt` | Reframe the reader’s assumption | One bold contrast, oversized word pair, minimal support copy |
| Problem card | `carousel_problem_card` | Make the pain or cost tangible | Friction label, short problem statement, small proof cue |
| Mistake card | `carousel_mistake_card` | Teach through a common error | Large ordinal number, false move, single corrective insight |
| Framework map | `carousel_framework_map` | Explain a memorable model | Three named parts with directional flow and a clear centre |
| Step card | `carousel_step_card` | Teach a practical sequence | Large step number, one action, one expected outcome |
| Checklist card | `carousel_saveable_checklist` | Create a save-worthy reference | Ticked actions, progress count, reduced visual noise |
| Proof card | `carousel_proof_snapshot` | Add credibility at the right moment | One metric, simple comparison bars, source label |
| Before / after | `carousel_before_after` | Make transformation visible | Clear two-column contrast, visual and verbal shift |
| Myth / truth | `carousel_myth_truth` | Correct a false belief succinctly | Split colour treatment, direct claim and clarification |
| Quote card | `carousel_quote_takeaway` | Add a human or founder takeaway | Large pull quote, attribution and utility tag |
| Closing CTA | `carousel_close_cta` | Convert attention into a next action | Specific save/share/comment prompt and compact recap |

## Production rules

The cover is deliberately **not** a brand-intro slide. Brand identity appears consistently but quietly, while the reader-facing promise carries the visual priority. This is consistent with current carousel guidance that positions the first slide as the decisive swipe trigger. [1] [2]

Middle slides use the same visual skeleton: an ordinal marker, a display headline, one short support unit, and one restrained accent. This preserves recognition from slide to slide, lowers cognitive load, and creates a clear reader rhythm. The closing slide uses an explicit action rather than a vague request for engagement.

| Element | Implementation standard |
| --- | --- |
| Cover hook | 4–9 words whenever possible; use a question, tension, result, or numbered promise |
| Middle-slide headline | 3–8 words, large enough to understand at mobile preview size |
| Supporting copy | One sentence, one quote, or three concise checkpoints; no dense paragraphs |
| Visual accent | One per slide: ordinal, highlight, metric, icon, arrow, or contrast field |
| Branding | Small brand mark in a stable corner, never a competing centrepiece |
| Deck length | Use 5–10 slides for a standard teaching deck; omit unneeded roles rather than filling space |
| Closing action | Use a single explicit behaviour: save, send, comment, or apply |

## Example sequence

For the message **“Most missed calls are not a volume problem. They are a context problem.”**, a seven-slide deck could use the following roles: Cover hook; Problem card; Pattern interrupt; Framework map; Step card; Proof snapshot; Closing CTA. This sequence teaches one coherent idea without needing every template in the library.
